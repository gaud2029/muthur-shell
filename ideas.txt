UPDATES: what's left after [UPD] (pacman -Syu only for now)
-----------------------------------------------------------

Done: Updates.qml (checkupdates at login + 1 min, hourly, after a
resume, on demand; retry 5 min after a failure), the [UPD] button and
panel (important packages first, REBOOT REQUIRED), UPGRADE = `sudo
pacman -Syu` in a detached terminal that asks the shell to recheck,
`!update` in the launcher, `muthur updates [list|check|upgrade]`,
pacman-contrib in install.sh.

Still to do:
  - topgrade: run it instead of pacman -Syu when installed.
    - Not in the Arch/CachyOS repos: an install.sh extra that builds
      `topgrade-bin` from the AUR with makepkg (no helper needed), or
      `cargo install topgrade`.
    - dotfiles/topgrade/topgrade.toml, symlinked to ~/.config:
        [linux] arch_package_manager = "autodetect"
        [misc]  disable = [...] (firmware, git_repos... to decide)
    - Don't run alongside CachyOS's own updater (cachyos-update).
  - Arch news in the panel: the archlinux.org/feeds/news RSS feed; flag
    any item newer than the last time the panel was opened (some
    updates need a manual step). A link opens it in Firefox.
  - flatpak, if installed: `flatpak remote-ls --updates` in the count.
  - AUR, once a helper is installed: `paru -Qua`.
  - Settings (Cli.qml registry + a panel): updates.check (on/off),
    updates.interval (minutes), updates.flatpak (on/off).
  - An optional notification when the count first rises above 0 (off
    by default).
  - The patched labwc (labwc-snapgrid) isn't tracked by pacman: compare
    its version with `pacman -Si labwc` and show "labwc 0.x available:
    ./install.sh --extras labwc".
  - Try the whole flow on a plain Arch in the test VMs (vm/muthur-vm).
